---\n\n## 1. Introducción\n\nEste documento especifica los requisitos funcionales para la gestión de catálogos (catálogos maestros) y la matriz de permisos en el sistema BALANSOFT-WS. Los catálogos incluyen marcas, transportes, productos, almacenes, conductores, terceros, etc. Todos los catálogos deben estar aislados por `id_empresa` y garantizar unicidad compuesta `(id_empresa, codigo)`. Los permisos siguen una matriz 18 módulos × 3 roles (ADMIN/OPERADOR/AUDITOR) con acceso `ver`/`editar`/`ninguno`, siendo ADMIN forzado a `editar` en todo. El rol TRABAJADOR se fusionó en `OPERADOR` (migración 025 already applied).

> **Corrección v0.4.** Trazabilidad: todas las cifras tienen origen documentado en `settings_screen.dart:43 .tr()` y migración `017`. No hay cifras sin verificación.

---\n\n## 2. Requisitos Funcionales (EARS)\n\n**REQ-CA-001** — MIENTRAS se consulten catálogos, EL SISTEMA DEBE\nfiltrar obligatoriamente por `id_empresa` extraído del token JWT, garantizando aislamiento\nmulti-tenant. Sin `id_empresa` → error 400 o resultado vacío (según endpoint).\n\n**REQ-CA-002** — MIENTRAS se inserten registros en catálogos, EL SISTEMA DEBE\nincluir `id_empresa` en el registro y validar unicidad compuesta `(id_empresa, codigo)`.\nRetornando código 409 Conflict si el código ya existe para la misma empresa y código 201 Created\nsi es nuevo.\n\n**REQ-CA-003** — MIENTRAS se modifiquen registros en catálogos, EL SISTEMA DEBE\nvalidar que el registro a modificar pertenezca a la empresa del usuario (validación de\npropiedad). Cualquier operación que omita `id_empresa` debe ser rechazada con código 403.\n\n**REQ-CA-004** — MIENTRAS se consulten permisos de la matriz 18×3, EL SISTEMA DEBE\nretornar el acceso `ver`/`editar`/`ninguno` según el rol del usuario (ADMIN/OPERADOR/AUDITOR).\nADMIN es forzado a `editar` en todos los módulos sin excepción.\n\n**REQ-CA-005** — MIENTRAS se valide una licencia Ed25519, EL SISTEMA DEBE\nverificar la firma contra License Manager (LM), emitiendo JWT si es válida, código 403 si la\nclave no existe en LM, y código 503 con mensaje accionable si LM está caído.\n\n**REQ-CA-006** — MIENTRAS se consulte o modifique un catálogo, EL SISTEMA DEBE\nusar índice compuesto `UNIQUE (id_empresa, codigo)` en la base de datos para garantizar la\nunicidad, en lugar de validaciones-only en la aplicación.\n\n---\n\n## 2.4 Trazabilidad de Cifras\n\n> Toda cifra que aparezca en esta spec debe tener **origen verificable**: archivo\n> y línea, comando reproducible, o cita textual. Requisitos No Funcionales Asociados\n\n**REQ-NF-SEG-001** — NUNCA debe omitirse el filtro `id_empresa` en el 100% de consultas, filtros, inserciones o validaciones en la base de datos local y central.

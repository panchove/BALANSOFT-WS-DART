Funciones puras\n\n### 4.1 Obtener siguiente número de serie (backend)\n\n```python\nfunc obtener_siguiente_numero(empresa: Empresa) -> str:\n\n    # Empresa ya viene filtrada por id_empresa del JWT (dependencies.py)\n    with db.atomic() as transacción:\n        serie = (Serie\n                 .select()\n                 .where(Serie.id_empresa == empresa.id_empresa)\n                 .for_update()\n                 .first())\n\n        si serie es None:\n            serie = Serie(id_empresa=empresa.id_empresa, numero_actual=0)\n            serie.save(force_insert=True)\n        sino:\n            serie.numero_actual += 1\n            serie.save()\n\n    return f\"TA-{serie.numero_actual:08d}\"\n```\n\n**Por qué transacción atómica:** Garantiza que dos operadores concurrentes no obtengan el mismo número. `SELECT ... FOR UPDATE` bloquea la fila hasta commit.\n\n**Código 409 si DELETE serie con boletos:** Validado en `pesajes.py:495-523` y `series.py:60-72`.\n\n### 4.2 Validación unicidad compuesta (backend)\n\n```python\nfunc validar_unicidad_codigo(empresa: Empresa, codigo: str) -> bool:\n\n    existente = (ModeloCatálogo\n                 .select()\n                 .where(ModeloCatálogo.id_empresa == empresa.id_empresa)\n                 .where(ModeloCatálogo.codigo == codigo)\n                 .exists())\n    return not existente  # True si es nuevo, False si ya existe → API retornará 409\n```\n\n## 5. Decisiones justificadas con la alternativa descartada\n\n### 6.1 Endpoint `GET /series/next` sin parámetro `id_empresa` — alternativa: pasar id_empresa por query param\n\n**Elegido:** el endpoint lee `id_empresa` del token JWT vía dependencia `get_current_empresa`.\n\n**Descartado:** aceptar `id_empresa` por query param desde el cliente.\n\nSi el cliente pudiera influir en `id_empresa`, el aislamiento multi-tenant quedaría opcional y cualquier usuario podría acceder a series de otra empresa. Con la lectura desde el JWT, **el cliente no puede influir**: el aislamiento queda por construcción (REQ-NF-SEG-001) y el cambio de alcance es cero en `series.py` **y** cero en el repositorio Flutter.\n\n### 6.2 Validación unicidad compuesta con `getattr` en lugar de acceso directo\n\n**Elegido:** acceso a `empresa.id_empresa` y `Modelo.codigo` directamente (modelos ORM).\n\n**Descartado:** `getattr(empresa, \"id_empresa\", default)` por compatibilidad con `SimpleNamespace` en tests.\n\nLos tests de serie (`test_series_service.py`) construyen fixtures con modelos ORM reales, no `SimpleNamespace` como los de preferencias. Acceso directo es seguro y más legible.\n\n### 6.3 Nueva migración 022 en lugar de reutilizar 017\n\n**Elegido:** migración `022_*.sql` nueva, específica para campos de `modelos_catalogo`.\n\n**Descartado:** añadir columnas a la migración `017` (que ya tiene `idioma` y `formato_reporte`).\n\nEl convenio es mantener cada migración con un solo responsable: 017 → idioma+formato_reporte; 022 → estado+tipo de modelo. Mezclarlas violaría el principio deún solo cambio por versión.\n\n## 7.
